# DESIGN.md

Визуальный канон продукта. Источник правды — эталонные макеты в
[`docs/design/`](docs/design/), считанные из Claude Design проекта «CRM
визуальный язык: расписание кабинетов». Значения токенов — в
[`tokens.css`](tokens.css); этот файл объясняет смысл и правила, а не дублирует
числа.

Любой экран в `app/` верстается по этому канону. Где макета не хватает —
спрашиваем, не додумываем.

---

## 1. Позиция

Светлый рабочий инструмент по ощущению Linear / Stripe: много воздуха, почти
монохром, интерфейс не мешает работать. Плотность приходит от типографики и
выравнивания, не от рамок. Администратор сидит в системе всю смену — экран не
должен утомлять.

Контент лежит в **карточках со светлой границей на почти-белом фоне**, а не в
тяжёлых панелях. Один акцент — индиго. Он работает ровно в двух ролях:
**действие** (кнопка, активная навигация) и **свободное окно** (главная
ценность экрана «Сегодня»). Больше нигде цвета нет — данные различаются
положением, размером и насыщенностью серого.

Отменённые прежние направления (бежевый «Пульт», зелёный монохром) в канон не
входят. **Горизонтальной шкалы времени по кабинетам нет** — она убрана
намеренно, вместо неё карточки кабинетов и список окон. Не возвращать.

## 2. Цвет

Значения — в `tokens.css`. Роли:

| Токен | Роль |
|---|---|
| `--bg` `#FBFBFC` | фон приложения |
| `--sidebar` `#FCFCFD` | фон боковой навигации |
| `--surface` `#FFFFFF` | карточки, шапка, поля ввода |
| `--hover` `#F6F7F9` · `--nav-active` `#F1F1F6` | ховер и активный пункт |
| `--border` `#E6E8EC` · `--border-soft` `#EFF1F4` | границы карточек и внутренние разделители |
| `--text` `#15161B` · `--text-muted` `#565B66` · `--text-subtle` `#6C727D` | три ступени текста |
| `--accent` `#4B44C7` | действие и свободное окно |
| `--accent-text` `#3F39A7` | акцентный текст на светлом тоне |
| `--accent-tint` `#EDECF9` · `--accent-border` `#C2BFEC` | мягкая заливка неближайших окон |

### Контраст (жёсткое правило)

Всё видимое текстовое ≥ **WCAG AA**: 4.5:1 обычный текст, 3:1 крупный (≥ 24px
или ≥ 18.66px bold). Проверка автоматизирована — `node contrast-check.mjs`
обходит реально отрисованные узлы всех экранов и падает при нарушении. Гонять
после любой правки палитры или вёрстки.

**Отклонение от макета, намеренное и единственное по цвету.** Макет использует
две светлые серые ступени `#868C97` (≈3.4:1) и `#A7ADB7` (≈2.3:1) — обе ниже
AA. Тон сохранён, светлота опущена: вторичный текст `#565B66` (6.7:1),
приглушённый `#5E636E` (≥4.5:1, измерено на всех фонах). Самая светлая ступень для текста не
используется — только для декоративных элементов (точка-разделитель `.sep-dot`,
она не текстовый узел).

### Акцент — правила

- сплошной `--accent` под белым текстом (7.1:1) — кнопка, ближайшее свободное
  окно, активная точка;
- `--accent-text` — акцентный текст на белом (9:1) и на `--accent-tint` (7.7:1):
  активная навигация, заголовок «Свободно», неближайшие окна;
- **ближайшее свободное окно** заливается сплошным акцентом, остальные — мягким
  тоном `--accent-tint` с кромкой `--accent-border`. Так «когда ближайшее окно»
  читается без чтения списка;
- первичный пациент помечается точкой `--accent` 6×6, а не цветом текста.

Запрещено: второй акцентный цвет, цветовое кодирование направлений, любые
градиенты, полупрозрачные заливки под текстом.

## 3. Типографика

| Роль | Шрифт |
|---|---|
| Интерфейс | **Onest** 400 / 500 / 600 — кириллица в основе, спокойный |
| Числа и время | **JetBrains Mono** 400 / 500 — только цифры, `tabular-nums` |

Моноширинный — **исключительно** для чисел, времени, денег, счётчиков. Никогда
для текста, подписей, заголовков. Класс `.num`.

Шкала (`--text-*` в globals, значения из `tokens.css`):

| Утилита | px | Применение |
|---|---|---|
| `text-2xs` | 11 | мелкие метки, счётчики |
| `text-xs` | 12 | подписи, вторичные строки |
| `text-sm` | 13 | основной текст строк, пункты навигации |
| `text-base` | 14 | текст, названия в карточках |
| `text-md` | 15 | заголовок карточки кабинета |
| `text-lg` | 18 | название клиники в сайдбаре |
| `text-xl` | 20 | заголовок экрана |
| `text-data` | 21 | время в строке окна (mono) |
| `text-2xl` | 30 | крупное число свободного окна (mono) |

Заголовки и подписи — обычным регистром, вес 500–600. **Капса нет** (ни в
подписях, ни в заголовках секций). Прописные не применяются к именам и
названиям процедур.

## 4. Форма, сетка, ритм

- Радиусы (`tokens.css` `--r-*`): чипы 5, кнопки/поля 8, внутренние блоки 10,
  карточки и списки 12, внешняя рамка составного блока 14, пилюли-счётчики 20,
  аватар круглый. **Скругления есть** — это не «Пульт».
- **Теней нет.** Ни `box-shadow` под карточками, ни у оверлеев — глубину
  оверлея даёт затемняющая подложка `.overlay-scrim`, а не тень. Единственная
  «тень» — обводка `:focus-visible`.
- Границы: карточка — `--border`; разделители внутри карточки — `--border-soft`;
  строки списка разделяются фоном-щелью `--list-gap` (1px просвет), не рамкой.
- Ритм — шаг 4px (`--sp-*`). Внешние поля контента: 20px мобильно, 28px от
  карточек к краю на десктопе.
- Карточки равной высоты в ряду по 3 (кабинеты); списки — строками полной
  ширины.
- Вложенных «коробка в коробке» избегаем: карточка → строки/блоки внутри,
  глубже не вкладываем.

## 5. Несущие конструкции

### Боковая навигация (232px)

Слева на всех экранах: логотип «Мера», пункты (Сегодня · Диалоги · Пациенты ·
Курсы · Кабинеты · …), внизу — профиль администратора. Активный пункт —
подложка `--nav-active` + текст `--accent-text`. У «Диалогов» счётчик
непрочитанного пилюлей. На узкой ширине сворачивается.

### Глобальный поиск ⌘K

Несущий по IA: пациент достаётся из любой точки. Поле в шапке + модалка по ⌘K /
Ctrl+K. Принимает телефон, имя, номер записи.

### Экран «Сегодня» — signature

Не отчёт, а «что сейчас». Шапка со сводкой смены (выручка, средний чек, число
записей, первичные, время). Три **карточки кабинетов**: направление, врач,
текущий приём, «занят до», и крупным mono-числом — **следующее свободное окно**.
Ниже — единый **список свободных окон** по всем кабинетам до конца дня,
отсортированный по времени; ближайшее выделено сплошным акцентом. Плюс блоки
«Требует внимания» и «Новые обращения» в той же карточной логике.

### Карточка пациента — одна вёрстка, два места

Один компонент рендерится и как **колонка 320px** (третья колонка «Диалогов`),
и как **узкая панель-оверлей** поверх любого экрана. Разница только в обёртке
(колонка против `.overlay-scrim` + панель справа), содержимое идентично:
контакты, история визитов, активные курсы с прогрессом, переписка, источник
первого обращения.

### Панель записи — оверлей

Поверх экрана, справа. Подбор окна под услугу/врача. **Перед созданием слот
перепроверяется в YCLIENTS в реальном времени** — состояние «проверяем…» → «слот
свободен, записать» / «слот занят, обновить». Это не косметика, а
архитектурное требование: YCLIENTS — источник истины по расписанию.

## 6. Состояния

Каждый экран реализует: загрузка (скелетон в логике направления, не серые
полоски), пусто, ошибка чтения, длинные фамилии (двойная с отчеством),
четырёхзначные числа, 375px. Проверяются на служебном `/states`, а не на живых
данных.

Интерактив: `:hover` — смена фона на один шаг, без движения; `:focus-visible` —
обводка акцентом; переходы только по цвету/фону ≤120мс и отключаются при
`prefers-reduced-motion`.

## 7. Запрещено (сводно)

- Возврат горизонтальной шкалы времени по кабинетам — в любом виде.
- Бежевый / «Пульт» / материальные метафоры; второй акцент; градиенты; тени под
  карточками.
- Моноширинный для текста; капс в подписях и заголовках.
- Хардкод цвета или размера в компоненте — только токены из `tokens.css`.
- Шрифты Inter, Roboto, Open Sans, Arial, system-ui, IBM Plex.
- Библиотеки графиков — всё на CSS/SVG. Эмодзи-иконки.
